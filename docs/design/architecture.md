# 架构说明

本文档说明 HelloYunhu 的模块划分、数据流、并发模型与错误处理。它对应 M1 完成时的实现，后续里程碑会补充媒体、持久化与限流部分。

## 1. 两条连接

程序只发起出站连接，不需要公网地址。每个机器人实例对应两条连接：

| 连接 | 方向 | 作用 |
|---|---|---|
| 订阅连接 | `wss://ws.jwzhd.com/subscribe` | 接收云湖推送的事件 |
| 框架连接 | `ws://框架地址/ws` | 向框架推送事件，接收框架发来的接口调用 |

框架连接的握手头固定为 `X-Self-ID`、`X-Client-Role: Universal` 与可选的 `Authorization: Bearer`。`X-Self-ID` 取自云湖 `/bot/info` 返回的 `botId`，因为云湖事件本身不含机器人标识。

## 2. 模块与依赖

```
cmd/helloyunhu          命令行入口，解析参数、创建上下文、调用 app
internal/app            装配：读取配置、创建日志、按实例启动连接
internal/config         配置结构、默认值、加载与校验
internal/logging        log/slog 初始化
internal/yunhu/model    云湖事件与接口的数据结构
internal/yunhu/api      云湖接口客户端
internal/yunhu/subscribe 订阅连接
internal/onebot/model   OneBot 事件、消息段与响应
internal/onebot/client  反向 WebSocket 连接、回显匹配
internal/onebot/action  接口调用实现
internal/bridge/identity 标识映射
internal/bridge/message 消息段与云湖消息的转换
internal/bridge/event   云湖事件到 OneBot 事件的转换
```

依赖方向是单向的：`cmd` 依赖 `app`，`app` 依赖其余所有包；`bridge` 同时依赖两侧的模型，两侧的模型互不依赖；`yunhu` 与 `onebot` 之间没有直接依赖。这样云湖侧调整只影响 `yunhu` 与 `bridge`，OneBot 侧兼容性调整只影响 `onebot` 与 `bridge`。

## 3. 数据流

**接收方向。** 订阅连接读到一帧，解析成事件外壳后写入事件通道。转发协程取出外壳，按事件类型解析负载，换算标识，构造 OneBot 事件，再写入框架连接。事件通道容量为 64，写满时订阅连接的读循环会等待，背压传导到网络层，事件不会在内存里无限堆积。

**发送方向。** 框架写入一帧接口调用，连接层按 `action` 与 `params` 解析，交给接口处理器。处理器把消息段整理成云湖文本消息，调用 `/bot/send`，把返回的消息标识登记到映射表，最后按 OneBot 格式写回响应。响应必须带回框架给出的 `echo` 原对象，否则框架会等到超时。

**连接建立。** 框架连接握手成功后，立即发送 `meta_event.lifecycle.connect` 事件，框架据此打印「已连接」并开始工作。

## 4. 并发模型

每个实例启动三个常驻协程：

| 协程 | 职责 |
|---|---|
| 订阅连接 | 读事件、重连、写入事件通道 |
| 框架连接 | 读接口调用、写事件与响应、重连 |
| 事件转发 | 转换事件、写入框架连接 |

每个接口调用额外启动一个协程，避免一次慢调用阻塞读循环。框架连接上的写入由互斥锁保护，并设置 10 秒写超时；读取上限放大到 64 MB，因为框架会把图片与语音整段内联成 base64。

上下文取消时，两个连接都会主动关闭自身，读循环不会阻塞到对端断开。实例出错时取消同进程内其它实例。

## 5. 错误处理与重试

| 场景 | 处理 |
|---|---|
| 订阅连接或框架连接断开 | 按 1 秒到 30 秒的指数退避重连，连接成功建立过后重置间隔 |
| 发送消息失败 | 不重试，错误如实返回给框架，并记录日志 |
| 云湖返回业务错误码 | `*APIError` 包装错误码，`1007` 表示触发频率限制，可用 `errors.Is(err, api.ErrRateLimited)` 判断 |
| 调用频率 | 客户端按 `yunhu.rate_limit` 匀速放行，默认每秒十次，等待受上下文控制；超限错误不自动重试 |
| 接口未实现 | 返回 `retcode=1404` 与说明，不返回成功 |
| 参数不合法 | 返回 `retcode=100` 与说明 |
| 其它内部错误 | 返回 `retcode=1500`，说明写进 `wording` |
| 事件解析失败 | 记录日志并跳过这一条，不中断连接 |
| 暂不支持的消息内容 | 转为占位文本，用户至少能看到提示 |

发送路径不自动重试是有意为之：机器人重复发言的代价高于一次发送失败，失败信息交给日志与接口返回值。

## 6. 标识映射

云湖的用户、群与消息标识都是字符串，其中消息标识是 32 位十六进制；OneBot 的多处代码要求整数。

用户与群标识是十进制数字，直接解析即可。消息标识需要一张表：接收消息时分配递增整数，发送引用时反查回原始标识。

映射表存放在 SQLite 中，使用纯 Go 驱动，不依赖 cgo。云湖的消息标识唯一，整数由自增主键分配，重启后再查同一个标识会拿到同一个整数，引用与撤回因此不会因为重启而失效。写入采用先查后插：命中时不写库，避免自增序列被无效写入消耗；插入使用 `DO NOTHING`，并发写入时重新查询取得已分配的整数。连接池限制为单连接，并发调用排队而不是遇到锁冲突。

映射表按保留时长清理，启动时先清理一次，之后每小时一次。消息标识的增长速度远快于用户与群，不清理会无限膨胀。

解析失败时退化为稳定哈希，并在转换层记录一次日志。这样标识仍然可比较，但已经失去可读性，属于需要关注的异常。

## 7. 当前限制

- 消息内容覆盖文本、图片、文件、视频与语音。语音接收为 `record` 段，发送按文件消息处理，因为云湖没有语音发送能力。
- 图片、文件、视频与语音在接收方向都先下载再以 base64 交给框架，体积上限由媒体读取器控制；下载失败时退化为直接给出地址。四类媒体的 CDN 地址规则见 [协议映射说明](protocol-mapping.md) 第 3 节。
- @ 段按正文里的提及位置切分，正文里没有对应的 `at` 时保留原文。
- 撤回依赖进程内的消息归属缓存，重启后撤回旧消息返回 1404；平台不推送撤回通知。
- 通知类事件（关注、入群、退群）尚未转换，收到时记录日志并跳过。
- 心跳事件尚未发送。首个验收框架不依赖它，其它框架在后续补齐。
- 群成员接口需要机器人在群后台获得权限，未授权时降级为空数据，保住 @ 唤醒。

## 8. 只读诊断接口

配置 `diagnostics.enabled` 为真时，进程在 `diagnostics.listen` 上启动一个只读 HTTP 服务，提供两个端点：

| 端点 | 内容 |
|---|---|
| `GET /healthz` | 返回 `ok`，用于探活 |
| `GET /status` | 返回 JSON：版本、启动时间、运行秒数、实例数量、已处理事件数与调用数 |

服务只读，写请求返回 405，不输出消息正文、令牌与用户标识。默认关闭，开启后建议只监听回环地址。

## 9. 自检与调试

`selftest` 子命令对每个实例做三项真实检查：查询机器人信息、握手订阅端点、握手框架端点。检查只建立连接后立即关闭，不进入消息循环，因此可以在正式启动前反复执行，也不会让框架登记成可用连接。任一检查失败时退出码为 1。

排查协议问题时把日志级别设为 `debug`，并打开 `log.raw_events`。该开关输出订阅收到的原始事件帧，长度截断到 4 KB；关闭时只记录事件类型与解析错误。接口返回非零错误码或响应无法解析时，错误信息会带上响应原文片段，避免为了确认字段名再加临时打印。
