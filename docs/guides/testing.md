# 测试指南

本文档说明如何用真实的云湖机器人与机器人框架跑一轮测试。内容按操作顺序组织，每一步都给出预期结果，便于判断问题出在哪一层。

## 1. 准备配置

在仓库根目录新建 `config.yaml`，内容参考 `examples/config.yaml`。最少需要填两项：云湖机器人令牌，以及框架监听的地址。

```yaml
log:
  level: debug
  format: text
  # 排查协议问题时设为 true，会输出收到的原始事件。
  raw_events: true
  # 日志文件路径。设置后同时写终端与文件，追加写入，不做轮转。
  file: logs/helloyunhu.log

instances:
  - name: main
    token: "云湖机器人令牌"
    onebot:
      url: ws://127.0.0.1:8080/onebot/v11/ws
      access_token: ""
```

`config.yaml` 与 `data/` 已经在 `.gitignore` 中排除，不会被提交。令牌泄露时到机器人后台重置。日志目录不在忽略列表里，但日志文件可能包含群标识与昵称，分享前先检查。

框架侧先不设置访问令牌，`access_token` 与框架配置里的令牌都留空，把协议跑通后再加认证。

## 2. 先跑自检

```
helloyunhu selftest -config config.yaml
```

自检会真实发起三次连接：查询机器人信息、建立一次订阅连接、向框架握手。每项输出通过、失败或跳过，失败时退出码为 1。

正常情况下应当看到：

```
[通过] 配置检查: config.yaml，共 1 个实例
[通过] 实例 main · 机器人信息: botId=… 昵称=…
[通过] 实例 main · 订阅连接: 握手成功
[通过] 实例 main · 框架握手: 握手成功
```

常见失败与含义：

| 输出 | 含义 | 处理 |
|---|---|---|
| 机器人信息返回错误码 1003 | 令牌无效 | 到机器人后台核对或重置令牌 |
| 订阅握手失败，状态码 401 | 订阅端点拒绝当前令牌 | 同上；令牌正确时检查订阅地址 |
| 框架握手失败，状态码 400 | 头部不合要求，或路径不是反向 WebSocket 端点 | 检查框架是否已启动、路径是否正确 |
| 框架握手失败，连接被拒绝 | 框架没有监听 | 先启动框架，或修正地址与端口 |

框架握手需要机器人标识，所以机器人信息失败时这一项会标记为跳过。

## 3. 启动顺序

先启动机器人框架，再启动 HelloYunhu。HelloYunhu 是主动连接的一方，顺序反了会按 1 秒到 30 秒的退避不断重连，直到框架起来。

```
# 终端一：框架
nb run

# 终端二：HelloYunhu
helloyunhu run -config config.yaml
```

启动后日志里应当依次出现：程序启动、装载机器人实例、已连接机器人框架、已连接云湖事件订阅。

## 4. 启动测试机器人

仓库自带一个基于 NoneBot2 的测试机器人，放在 `tools/testbot/`。它提供两个插件：`echo` 把收到的消息回显，`diagnostics` 在收到 `/diag` 时回复事件的关键字段。后续新增测试场景时在它的 `plugins/` 目录下扩展。

首次运行会自动创建虚拟环境、安装依赖并生成 `.env`：

```powershell
cd tools\testbot
.\run.ps1
```

也可以手动执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe bot.py
```

启动后它监听 `127.0.0.1:8080`，反向 WebSocket 端点是 `ws://127.0.0.1:8080/onebot/v11/ws`，与 `config.yaml` 里的 `onebot.url` 保持一致。框架侧配置见 `tools/testbot/.env.example`，可以修改端口。

框架的访问令牌两侧都留空时不需要额外配置。

## 5. 测试清单

| 场景 | 操作 | 预期 |
|---|---|---|
| 群聊文本 | 在群里发一句普通消息 | 框架收到 `message.group`，回声插件回一条文本 |
| 群聊 @ | 在群里 @机器人 发一句话并带内容 | 框架收到文本段前有 `at` 段，回声正常 |
| 引用回复 | 发 `/quote` | 云湖侧显示为引用回复，日志里的发送请求带 `parentId` |
| 指令消息 | 在客户端用 `/quote` 指令发 `test` | 框架收到的正文是 `/quote test`，命令能匹配 |
| 图片接收 | 发一张图片 | 框架收到 `image` 段，内容为 `base64://` |
| 文件接收 | 发一个文件 | 框架收到 `file` 段并带地址与文件名 |
| 视频接收 | 发一段视频 | 框架收到 `video` 段并带地址 |
| 私聊接收 | 在私聊里发一句话 | 框架收到 `message.private`，回复可达 |
| 自身消息 | 机器人自己发言 | 框架不应收到机器人自己的消息 |
| 诊断命令 | 群里或私聊发 `/diag` | 回复 `self_id`、`message_id`、`group_id` 与消息段类型 |
| 图文混排发送 | 发 `/m2check`，或让框架在一条消息里回复文本、图片、文本 | 云湖出现三条消息，顺序为文本、图片、文本 |

`/diag` 用于确认映射结果：群里 @ 机器人时 `segments` 应包含 `at`，发图片时应包含 `image`，`message_id` 应当是可转换为整数的值。

群成员类查询需要机器人在群后台获得成员列表权限，没有授权时接口返回 1003，转换层降级为空列表。这种情况下 @ 唤醒仍然可用，但 `get_group_member_list` 拿不到人。

撤回、禁言、踢人与关注、入群、退群等通知事件尚未实现，测试时不出现反应属于预期行为。

## 6. 自动验收脚本

`tools/testbot/plugins/m2accept.py` 可以主动调用一组接口，不需要真人发消息就能覆盖发送与查询路径。在 `.env` 里填两项后启用：

```
M2_CHECK_GROUP=测试群号
M2_CHECK_USER=群主或管理员的 QQ 号
```

HelloYunhu 连上框架时脚本会自动执行一轮，也可以在群里发送 `/m2check` 手动重跑。结果写入 `tools/testbot/.m2check/result.json`，日志里每步输出一行 `M2 通过` 或 `M2 失败`。

覆盖的步骤依次是：机器人信息、群列表、群信息、群成员列表、群成员信息、发送文本、发送图文混排、发送 @、发送图片、发送文件、发送视频、发送私聊、本地状态。素材在运行时生成：图片与文本文件由脚本直接写出，视频调用本机 `ffmpeg`，找不到 ffmpeg 时跳过视频一步并注明。

重启验证分两轮：第一轮记下结果里的 `message_id`，重启 HelloYunhu 后把 `M2_CHECK_REPLY_TO` 设为该值再启动框架，脚本只发一条引用回复，日志里 `parent_id` 不为空说明落盘映射仍然有效。

脚本会向群里发消息，只在测试群使用，正常运行时不要让这两项出现在 `.env` 里。

## 7. 采集现场信息

排查协议问题时把日志级别设为 `debug`，并把 `log.raw_events` 设为 `true`。日志会输出订阅收到的原始事件，长度截断到 4 KB。设置 `log.file` 后日志同时写入文件，终端与文件内容一致，反馈问题时直接给文件路径即可。

原始事件包含消息正文与昵称，只在本机排查时开启。提交问题或发给他人之前，先删掉令牌、群标识与用户昵称。

debug 级别还会输出两类便于定位的记录：`收到接口调用` 显示框架调用了哪个接口，`发送消息` 显示接收方、内容类型与 `parent_id`。其中 `parent_id` 为空说明引用没有生效在上游。

接口返回错误时，日志会带上响应原文的片段，例如：

```
云湖接口 GET /bot/info 返回错误码 1003: 非法token（原始响应: {"code":1003,"msg":"非法token"}）
```

这段原文是判断字段名是否与实现一致的关键，反馈问题时请一并提供。

图片与文件由转换程序下载后再交给框架。云湖的媒体 CDN 校验来源，下载时会自动附带 `Referer: https://myapp.jwznb.com`，缺少这一项会返回 403。

## 8. 已知限制

- 通知类事件（关注、入群、退群）记录日志后跳过。
- 撤回、禁言、踢人未实现，接口返回 1404 与说明。
- 心跳事件未发送，首个验收框架不依赖它。
- CQ 码只支持入口方向，事件固定以消息段数组发出。
- `get_msg` 只能回放进程内收到的消息，重启或超过保留时长后返回 1404；发送出去的消息不进缓存。
